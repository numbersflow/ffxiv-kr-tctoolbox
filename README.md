# 하베스트 (Harvest)

한국 서버 Dalamud API 15용 재배 작업자. TCToolbox의 재배 실행기와 필요한 공통 코드만 남겼다. 재배 외 도구상자 모듈과 기존 무소유 재배 IPC는 제공하지 않는다.

## 사용

1. WorkflowOrchestrator, GatherBuddyReborn, Lifestream, vnavmesh와 함께 로드한다.
2. 워크플로우의 **화단** 탭 또는 `/harvest`에서 작물·꽃·씨앗을 보고 선택한다. 목표 보유량은 품목마다 지정하며 여러 품목을 선택할 수 있다. 등록 화단 탭에서 사용할 칸을 선택하고 현재 상태와 경로를 확인한다.
3. 워크플로우 제작 재료 목록에서 재배할 품목을 선택하면 전체 확장팩의 미완료 기본 제작수첩 재료를 기준으로 계산한다.
4. 화단의 각 칸 또는 실내 화분을 선택하고 상호작용 가능한 위치에서 등록한다. 같은 화단은 같은 시설 이름과 시계 방향 칸 번호 0~7을 사용한다. 해당 시설까지 이동하는 Lifestream 경로도 지정한다.
   직접 걷는 접근 경로는 워크플로우의 등록 화단에서 시설 이름·Lifestream 도착 경로를 정하고 `경로 저장 시작`을 누른 뒤 걸어서 기록한다. `기록 종료·저장` 시 출발·꼭지점·도착만 저장하며 같은 시설 이름으로 다시 기록하면 경로를 교체한다. 저장된 점들은 Lifestream의 `MoveEx`를 통해 순서대로 따라간다. 구역 변경·순간이동·기록 연결 종료는 저장하지 않고 취소한다. 기존 설정의 접근 좌표 방식도 계속 지원한다.
5. 워크플로우의 **재배** 작업을 켜고 원하는 순위에 둔다. 신규 설치는 꺼짐이다. 목표가 없거나 목표 보유량을 충족하면 방문하지 않는다.

인벤토리·집사 재고를 먼저 사용하고, 부족한 기본 씨앗·흙·색상 비료는 GBR의 기존 보충 경로로 확보한다. 교배 씨앗은 선행 씨앗부터 생산한다. 교배는 인접한 두 등록 칸을 사용하며 한쪽 부모를 유지한다. 부모 씨앗이 소진되면 기존 작물을 수확한 뒤 선행 단계부터 다시 준비한다. 꽃 색상은 필요한 색상 비료를 순서대로 사용한다. 확률이 개입하는 교배·꽃 색상은 결과 재고를 확인하고 목표까지 반복한다. 횟수나 완료 날짜를 보장하지 않는다.

관리 간격은 12시간이다. 성장 중에는 워크플로우를 점유하지 않는다. 열린 조건부 낚시·채집 기회가 있으면 현재 한 칸의 조작을 마친 뒤 제어권을 넘긴다. 등록 위치와 현재 주택 식별이 일치하지 않거나, 재고·메뉴·작물 상태가 불명확하면 새 조작을 보내지 않는다. 기존에 심어진 외부 작물을 임의로 수확·폐기하지 않는다.

캐릭터별 목표·시설·단계·미확정 조작을 저장한다. 재로드 후에는 실제 칸과 재고를 재확인한다. 미확정 수확·비료 사용은 자동 재전송하지 않는다. 기존 `TCToolbox.json`이 있으면 백업 후 가져오되 기존 모듈 스위치로 자동 실행하지 않는다.

## 빌드와 검사

```powershell
$env:DALAMUD_HOME = 'C:\dev\dalamud\sources\Dalamud\bin\Debug'
dotnet build Harvest/Harvest.csproj -c Release
dotnet run --project checks/GardeningKR/GardeningKR.Checks.csproj -c Release
```

검사는 실제 한국 클라이언트 데이터 경로를 사용한다. 2026-11-16 기준 재배 결과 300종, 씨앗 108종, 교배 3,768행과 33개 호환성·계획 검사를 확인했다. 이는 게임 내 주택 이동·심기·관리·수확·장시간 교배를 검증한 결과가 아니다. 실제 주택 등록 후 현장 검증이 필요하다.

## 필요 수량과 수동 수확 반영

일반 재배는 `ceil((필요 수량 - 인벤·집사 보유량) / 칸당 기본 수확량)`으로 새 칸과 씨앗·흙을 예약한다. 구름도토리 8개는 칸당 5개 기준 2칸이다. 이미 심었거나 처리 결과 확인 중인 칸은 수량이 줄어도 보존한다. 교배의 부모 칸·확률 계산에는 일반 작물 수확량을 적용하지 않는다.

수동 수확량은 기존 재고 조회 주기(5초)에 반영한다. 인벤과 전체 보유량이 함께 늘면 같은 작물의 등록 칸을 다시 확인한다. 보유량만 보고 특정 칸을 비웠다고 추정하지 않는다. 현장에서 빈 칸을 확인하면 기존 목표를 완료하고 다음 품목이나 선행 교배 단계로 계획을 전환한다. 미확정 조작은 별도 결과 복구 절차를 유지한다.

`Harvest/Data/crop-yields.json`은 2026-11-17 [FFXIV Gardening 씨앗 목록](https://www.ffxivgardening.com/seed-list.php)의 품목별 기본 수확량을 대조한 데이터다. 각 `source`는 `https://www.ffxivgardening.com/seed-details.php?SeedID=<source>`의 식별자다. 예: [구름도토리](https://www.ffxivgardening.com/seed-details.php?SeedID=80). 기본 수확량은 라노시아·다날란 흙 기준 첫 수치이며, 흑의장막 흙의 수확량 보너스는 포함하지 않는다. 일반 재배는 기존대로 상점의 화분용 흙을 사용한다. 꽃은 1개이며, 미확인 새 품목은 과소 예약을 피하도록 보수적으로 1개를 사용한다. 한국 데이터의 씨앗 값 결과 행 8188도 이 보수값을 유지한다.

## 광부 집사 흙 사전 비축

화단에서 선택된 품목에 선행 교배가 필요하면 등록·사용 중인 야외 재배 칸의 3회분을 교배용 흙 목표로 게시한다. 8칸은 24개이며, 등록 한도 24칸에서는 최대 72개다. 완료된 수동 수량 목표와 해제한 품목은 제외한다. 일반 재배·꽃에 사용하는 상점 화분용 흙은 광부 수행 대상이 아니다.

`Harvest.GetSoilVentureTargets`는 캐릭터 식별자와 `Targets` 배열(`ItemId`, `Name`, `TargetCount`)을 반환한다. Workflow의 `GardeningEnabled`가 켜져 있을 때 AutoRetainer가 이 목표와 GBR의 현재 인벤·집사 재고를 읽는다. 기존 재료 수행을 사용하는 광부 집사 중 한 명만 비축에 배정하며, 수행 중·회수 전 물량과 배정 직후 예약 수량도 반영한다. 재고가 충분하거나 화단 작업·품목 선택을 끄면 기존 제작수첩·업적 재료 선택으로 복귀한다. 레벨·장비·채집 수첩 해금 검사는 기존 집사 수행 조건을 그대로 따른다. 진행 중인 수행은 강제 교체하지 않고 다음 정상 재파견 때 적용한다.

## 방문 완료와 후속 작업

방문은 현재 계획에서 실행 가능한 조작을 모두 처리한 뒤 종료한다. 심기 직후 가능한 첫 색상 처리, 관리와 색상 처리, 수확 후 남은 수량의 재심기, 목표 완료 후 준비된 다음 품목을 같은 방문에서 이어간다. 수확으로 교배 단계가 완료되면 보존하던 성숙 부모도 현재 방문에서 다시 확인한다. 새 심기는 해당 계획의 씨앗·흙·색상 준비물이 갖춰진 뒤 시작하며, 관리·수확이 필요한 기존 작물은 재료 부족과 관계없이 방문할 수 있다.

관리 방문에서는 현재 계획의 소유 작물을 함께 관리해 다음 관리 시각을 맞춘다. 관리 시각은 실행기의 완료 기록과 새 작물 상태를 확인한 뒤 갱신한다. 미확정 관리 조작은 재접속 후 안전하게 다시 관리하며, 심기·수확·색상 재료는 기존 미확정 결과 복구 규칙을 유지한다. 한 칸의 조작 수와 방문에서 처리한 칸 수를 따로 추적한다. 성장 대기, 재료 부족, 미확정 조작, 마른 작물·다른 작물 보호를 완료와 구분해 보고한다.

`checks/GardenVisitLoop`는 실제 방문·재고 확인·결과 복구·재계획 함수를 추출해 실행한다. 게임 상태, 이동, 재고 IPC는 모의 값이다. 실제 이동 경로는 별도의 `checks/GardenWalkVisit`가 검사한다. 게임 내 장시간 교배 완료를 증명하는 검사는 아니다.
